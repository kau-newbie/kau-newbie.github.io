요약: JWT란 무엇일까

# JWT

공부하다보니 피하려해도 피할 수가 없었다. JWT란?

**JWT(JSON Web Token)**는 두 클라이언트 - 서버 간 안전하게 데이터를 json 형식으로 주고 받기 위한 토큰 형식이다.
> 전자 서명이 돼있다.(digital signature)
> - 전자 서명은 전송한 데이터의 위,변조 체크를 위해 사용한다.


## JWT 사용시점 흐름도 {#flow-section}

일전에 내가 하던 [프로젝트]()를 예시로 들면,

```

<Browser>
   │
   │ ① Spring Security 로그인 (JSESSIONID)
   ▼
<Spring Boot>
   │
   │ Authentication 확인
   │
   │ ② MediaMTX Access JWT 생성 <------------- 요 과정 중에 생성하게 된다.
   ▼
Thymeleaf
   │
   │ token 포함
   ▼
<MediaMTX>            <------------- 미디어mtx라는 서버에서 받았던 jwt를 spring에 넘겨서 검증 요청을 한다.
   │
   │ ③ authHTTP
   ▼
<Spring> /api/v1/mediamtx/auth
   │
   │ JWT 검증              <----------- 검증 완료시 200 OK를 응답하고, 그렇지 않은 경우 40x를 응답한다.
   ▼                                이 응답 결과에 따라 미디어mtx 서버에서는 사용자 연결을 거부하는 등의 동작을 수행할 것이다.
200 OK

```

이렇게 서버가 증명(varifying)만 하면 돼서, DB를 뒤져본다던가, 하는 오래 걸리는 작업을 하지 않는 장점이 있다.

또, 메모리에 계속 올려두고 세션 정보를 유지하지 않아도 되고, 서버가 분산환경일 때 세션 정보를 공유하는 기능이 없어도 된다.

단, jwt가 탈취당했다고 강제로 삭제시킬 순 없다. 

## JWT 형태

JWT 생긴 모냥을 좀 살펴봐야겠다.

JWT는 점(.)을 기준으로 3개의 파트로 나누어진 긴 문자열 형태를 가진다.

```

eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJzdWIiOiIxMjM0NTY3ODkwIiwibmFtZSI6IkpvaG4gRG9lIiwiaWF0IjoxNTE2MjM5MDIyfQ.SflKxwRJSMeKKF2QT4fwpMeJf36POk6yJV_adQssw5c

```

[이 사이트에서](https://www.jwt.io/) 만들어볼 수 있다.

제미나이씨의 설명을 보자.

##### 1. Header (헤더)

    내용: 토큰의 타입(JWT)과 암호화 알고리즘(예: HMAC SHA256 또는 RSA) 정보가 들어있습니다.

##### 2. Payload (페이로드)

    내용: 실제 전달할 데이터(Claim)가 들어있습니다. (예: 사용자 ID, 권한 정보, 토큰 만료 시간 등)
        > 주의: Payload는 단지 Base64로 인코딩된 것뿐이므로 누구나 쉽게 디코딩해서 안을 들여다볼 수 있습니다. 따라서 비밀번호나 개인정보 같은 민감한 데이터는 절대로 넣으면 안 됩니다.

##### 3. Signature (서명)

    내용: 서버만 알고 있는 비밀 키(Secret Key)를 이용해 `Header`와 `Payload`를 합쳐 **암호화한 값**입니다.

    역할: 누군가 Payload의 내용(예: userId: 123 -> userId: 1)을 몰래 조작하더라도, 서버의 비밀 키로 계산한 서명값과 맞지 않게 되므로 위조 여부를 즉시 감지할 수 있습니다.

    1. header + payload를 Base64 인코딩
    2. secret key로 서명(signature) 생성
    3. 최종 JWT = header.payload.signature

여기서 `base64`란 무엇일까?

#####  base64

[아주 좋은 영상 발견](https://www.youtube.com/watch?v=A8tO4D1Gtc0)

`base64`는 단순히 보내고자 하는 데이터를 6비트마다 끊어서 `ASCII`마냥 표에서 대조되는 문자로 바꾸는 *encoding/decoding* 방식을 말한다.

문제는 멀쩡한 문자들도 base64를 거치며 비트수가 늘어난다는 것인데, 굳이 필요할까?

영상에 따르면, 오늘날 대부분 웹으로 데이터를 주고 받는 세상이고, 이때 많이 사용하는 방식은 `html`, `json` 같은 문자열 방식이다.

와중에 *bianry*파일들, 예를 들어, 이미지, 음악 등등은 html이나 json에 한꺼번에 보내려면 (두 번 따로 보내지 않으려면),

binary를 문자열로 encoding (받고 나선 decoding)해주는 과정이 필요할 것이다.


아무튼 단순 문자열로 변환해주는 방식이라 대부분은 아래와 같이 중요한 정보를 제외한, 간단한 정보들을 payload에 담는다고 한다.

```json

{
  "sub": "12345",         // 사용자 고유 Primary Key 값 (Subject. db의 primary key 등을 사용한다.)
  "role": "ROLE_USER",    // 최소한의 권한 정보
  "iat": 1722800000,      // 토큰 발급 시간 (Issued At)
  "exp": 1722803600       // 토큰 만료 시간 (Expiration Time)
}

```

## 구현

구현할 차례이다. [프로젝트]() 내용을 보면 메서드나 컴포넌트들의 이해가 쉽다.

[아까 흐름도](#flow-section)을 보면, 

우선, `HomeController`에서 로그인 후 JWT를 만들어 발급하도록 한다.
> 마지막엔 return 'home'으로 home.html로 간다.

JWT는 `Model`에 `addAttribute()`로 저장될텐데, 이러면 *thymeleaf*에 의해 home.html의 <iframe> 태그에 src="" 값으로 알아서 넣어줄 것이다.

이 *view*로 그려진 **home.html**이 브라우저에 전달될 것이므로, (아까 return 'home'이었음을 떠올리자.) 사용자는 **JWT**를 받은 셈이 된다.

```java

// HomeController 안에서

private final MediaTokenService tokenService;
	
@Value("${mediamtx.url}")
private String mediaMtxUrl;

...

model.addAttribute("mediaMtxUrl", mediaMtxUrl);

...

if (isLoggedIn) {
            model.addAttribute("isLoggedIn", true);
            model.addAttribute("usrId", auth.getName()); // 로그인한 유저 아이디(username)
            model.addAttribute("status", "ONLINE");      // 로그인 후에만 장치 상태 보이기 (예시)
            
            String username = auth.getName();

            String token =
                tokenService.createToken(
                    username,
                    "cam1"
                );

            model.addAttribute(
                "mediaToken",
                token
            );
            ...
}

```

이렇게 model에 addAttribute로 token을 넣는 것을 확인할 수 있다.
> tokenService의 createToken()메서드를 사용했다. 얘도 당연히 만들어둬야 한다.

home.html에서는, 

```html

    <div class="card-body p-0 bg-black text-center" style="min-height: 250px;">
	    <iframe id="webrtc-frame" 
				th:src="|https://${mediaMtxUrl}/cam1/?token=${mediaToken}|"
	            style="width: 100%; height: 350px; border: none;" 
	            allow="autoplay; fullscreen; picture-in-picture">
	    </iframe>
	</div>

```

이런식으로 썼는데, 저 ${} 부분들이 **thymeleaf**에 의해 채워질 것이다. 
> controller안에서 @Value를 써서 ${mediamtx.url}로 `application.properties`에 적어둔 mediamtx.url을 찾은 뒤,
>
> addAttribute로 Model에 넣어둘 땐 **mediaToken**이란 이름으로 저장했기 때문에, thymeleaf가 채워줄 수 있는 것이다.

이제 **TokenService**를 만들 차례이다.

- 토큰 생성
- 토큰 검증

을 해야 하는데, 보통 이때 secret key를 사용한다. 인증서를 secret key로 암호화 한 뒤, 다시 받아 검증할 때도 다시 secret key를 쓴다.

```java

@Service
public class MediaTokenService {

	@Value("${jwt.secret}")
    private String secret;

    private Key getSigningKey() {
        return Keys.hmacShaKeyFor(secret.getBytes(StandardCharsets.UTF_8));
    }

    public String createToken(
            String username,
            String path
    ) {
    	long now = System.currentTimeMillis();
        long expirationTime = 5 * 60 * 1000; // 5분
        return Jwts.builder()                
        		.claim("username", username)
                .claim("path", path)
                .setIssuedAt(new Date(now)) // 토큰 발급 시간(iat) 
                .setExpiration(new Date(now + expirationTime)) // 토큰 만료 시간(exp) 
                .signWith(
                    getSigningKey()
                )
                .compact();
    }

	public Boolean validate(String token) {
		try {
			if (token == null || token.isEmpty()) {
	            // 토큰이 없으면 401 Unauthorized 반환 (MediaMTX가 접속 거부)
	            return false;
	        }
            // JWT 검증 
            Claims claims = Jwts.parserBuilder() // a map of claims
                .setSigningKey(getSigningKey()) // 보내기전 sign 할 때와 동일한 방식으로 signing할 키를 bytes[] 형태로 변환.  
                .build()
                .parseClaimsJws(token)   // set한 시크릿 키로 1. 구조 검증 2. signature 검증 3. 만료시간 검증을 수행함.
                .getBody();              // 마지막으로 검증 완료된 payload를 string 또는 claims 반환
            	

            return true;

        } catch (JwtException | IllegalArgumentException e) {
            return false; // 401 → 토큰 불일치
        }
	}
}

```

그 다음, mediamtx에서 서버로 json 데이터를 줄 떄 처리할 apiController이다.

<details>
    <summary>(apiController를 처음엔 getToken()으로 처리했는데, 꽤나 큰 이슈가 있었다.)</summary>
    아래는 클로드 코드의 답변이다.<br>
    <pre>
        token 필드와 query 필드는 서로 다른 역할입니다

        혼동하기 쉬운 부분인데, 정리하면:

        token 필드: mediamtx가 RTSP/RTMP 등에서 Basic Auth 자격증명으로 받은 password 값을 그대로 미러링해서 채우는 필드입니다. authMethod: jwt를 쓸 때 "JWT를 password 자리에 넣어서 보내라"는 공식 관례(rtsps://publish:<jwt>@host/path)를 위한 것이지, WebRTC의 ?token=... 같은 임의의 쿼리 파라미터를 자동으로 파싱해서 넣어주는 필드가 아닙니다.
        query 필드: 클라이언트가 URL에 붙인 쿼리스트링을 가공하지 않고 그대로 전달하는 필드입니다.

        즉 mediamtx는 ?token=eyJ... 같은 커스텀 쿼리 파라미터의 존재 자체를 모릅니다. 그냥 "쿼리스트링이 이렇게 왔다"는 raw 문자열만 넘겨줄 뿐이고, 그 안에서 뭘 꺼내 쓸지는 외부 인증 서버(우리 Spring 앱)의 몫입니다.
    
    </pre><br>
    결과적으로 query필드에서 token(jwt)를 파싱하게 되었다.
</details>

```java

@Slf4j
@RequiredArgsConstructor
@RestController             // 리턴되는 자바객체를 json으로 변환.
@RequestMapping("/api/v1")
public class HomeApiController {
	
	private final MediaTokenService tokenService;
	
	@PostMapping("/mediamtx/auth")
	public ResponseEntity<Void> getAuth(
	        @RequestBody MediaMtxJwtRequest request
	) {
		log.info("user={}, password={}, token={}, ip={}, action={}, path={}, protocol={}, id={}, query={}, userAgent={}",
		        request.getUser(), request.getPassword(), request.getToken(), request.getIp(),
		        request.getAction(), request.getPath(), request.getProtocol(), request.getId(),
		        request.getQuery(), request.getUserAgent());
		String jwt = extractTokenFromQuery(request.getQuery());
	    if (jwt == null) {
	        jwt = request.getToken(); 
	    }
	    if(tokenService.validate(jwt)) {
	        return ResponseEntity.ok().build();      // responseEntity는 reponse그 자체로, 응답을 ok(200)으로 할지말지 정할 수 있는 듯 하다.
	    }

	    return ResponseEntity.status(HttpStatus.UNAUTHORIZED) // unauthorized는 401이다.
	            .build();
	}

    
    private String extractTokenFromQuery(String query) {
        if (query == null || query.isEmpty()) return null;
        return UriComponentsBuilder.newInstance()
            .query(query)
            .build()
            .getQueryParams()
            .getFirst("token");
    }
}

```
